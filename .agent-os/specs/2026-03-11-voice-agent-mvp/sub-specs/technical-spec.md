# Technical Specification

This is the technical specification for the spec detailed in @.agent-os/specs/2026-03-11-voice-agent-mvp/spec.md

> Created: 2026-03-11
> Version: 1.0.0

## Technical Requirements

### Real-Time Audio Pipeline

- Twilio receives an incoming call to the PH number
- Twilio connects to our FastAPI WebSocket endpoint via Media Streams
- Incoming audio arrives as base64-encoded mulaw/8000 audio chunks
- Audio is forwarded to Gemini 2.5 Flash Live API (Native Audio mode)
- Gemini processes speech directly (no separate STT step) and returns audio response
- Response audio is converted to mulaw/8000 format and sent back through the Twilio WebSocket
- The loop continues until the caller hangs up

### Latency Target

- Total round-trip: < 1000ms (Gemini ~400-600ms + Twilio overhead ~300-400ms)
- Use streaming responses from Gemini to start playback before full response is generated
- System prompt includes filler phrases ("One moment...", "Let me check...") to mask processing time

### System Prompt Architecture

- Prompts stored as `.md` files in `prompts/` directory
- Each prompt file contains: business name, services, pricing, hours, FAQs, tone instructions, lead capture instructions, and language preferences
- A config mapping (JSON or .env) links Twilio phone numbers to prompt files
- Prompt is loaded once at call start and passed to Gemini as the system instruction

### Call Logging

- SQLite database with SQLModel ORM
- Log entry created at call start, updated at call end with duration and summary
- Conversation summary generated by Gemini at end of call (separate text API call)

## Approach Options

**Option A: Gemini Live API with Native Audio (Selected)**
- Pros: Direct audio-to-audio processing, lowest latency, natural HD voices, Taglish support, free tier eligible, built-in emotion/tone understanding
- Cons: Newer API (less community examples), requires WebSocket management, audio format conversion needed

**Option B: Traditional STT → LLM → TTS Pipeline (speech_recognition + Gemini text + pyttsx3)**
- Pros: More tutorials available, simpler individual components, easier to debug each step
- Cons: Higher latency (3 separate steps), robotic voice output, no tone/emotion awareness, worse Tagalog support

**Option C: Third-party Platform (Retell AI, Vapi)**
- Pros: Pre-built UI, faster to market, managed infrastructure
- Cons: Per-minute fees ($0.07-0.31/min) destroy margins, no control, platform dependency

**Rationale:** Option A gives us the best voice quality, lowest latency, and lowest cost. The Gemini Live API with Native Audio is production-ready and available on the free tier. This is the clear choice for an affordable PH-market product.

## Audio Format Handling

### Twilio → Gemini
- Twilio Media Streams sends: base64-encoded mulaw audio at 8000 Hz
- Gemini Live API accepts: PCM audio at 16000 Hz (16-bit, mono)
- Conversion needed: mulaw/8000 → PCM/16000 (using Python `audioop` or `pydub`)

### Gemini → Twilio
- Gemini Live API returns: PCM audio at 24000 Hz
- Twilio Media Streams expects: base64-encoded mulaw audio at 8000 Hz
- Conversion needed: PCM/24000 → mulaw/8000

### Libraries for Audio Conversion
- `audioop` (Python stdlib) — for mulaw ↔ PCM conversion
- `struct` (Python stdlib) — for byte manipulation
- No external audio libraries needed for MVP

## External Dependencies

- **`fastapi`** — Async web framework with native WebSocket support
  - Justification: Best Python framework for real-time WebSocket handling needed by Twilio Media Streams

- **`uvicorn`** — ASGI server to run FastAPI
  - Justification: Production-grade async server, standard pairing with FastAPI

- **`twilio`** — Official Twilio Python SDK
  - Justification: Generates TwiML responses, validates webhook signatures, manages phone numbers

- **`google-genai`** — Google Generative AI Python SDK
  - Justification: Official SDK for Gemini 2.5 Flash Live API with Native Audio support

- **`websockets`** — WebSocket client library
  - Justification: Needed for maintaining persistent connection to Gemini Live API

- **`sqlmodel`** — SQL ORM built on SQLAlchemy + Pydantic
  - Justification: Type-safe database models with Pydantic validation, perfect for FastAPI integration

- **`python-dotenv`** — Environment variable management
  - Justification: Load API keys and config from .env file

- **`pydantic-settings`** — Settings management
  - Justification: Type-safe configuration with environment variable support

## Local Development Workflow

### ngrok Setup (Critical for Twilio Testing)

Twilio requires a public HTTPS URL to send webhooks. During local development, ngrok tunnels your localhost to a public URL:

```
┌──────────┐     ┌──────────┐     ┌───────────────┐     ┌──────────┐
│  Phone   │────▶│  Twilio  │────▶│ ngrok tunnel  │────▶│ localhost│
│  Call    │◀────│  Cloud   │◀────│ (public HTTPS)│◀────│ :8000    │
└──────────┘     └──────────┘     └───────────────┘     └──────────┘
                                                              │
                                                              ▼
                                                        ┌──────────┐
                                                        │  Gemini  │
                                                        │ Live API │
                                                        └──────────┘
```

**Setup steps:**
1. Install ngrok and authenticate: `ngrok config add-authtoken YOUR_TOKEN`
2. Start FastAPI: `uvicorn app.main:app --reload --port 8000`
3. Start ngrok: `ngrok http 8000`
4. Copy the ngrok HTTPS URL (e.g., `https://abc123.ngrok-free.app`)
5. Set Twilio Voice URL to: `https://abc123.ngrok-free.app/voice/incoming`
6. Set Twilio Status Callback to: `https://abc123.ngrok-free.app/voice/status`
7. Call the Twilio number — full pipeline runs on your local machine

**Note:** ngrok free tier gives a random URL each restart. For persistent URLs, ngrok paid ($8/mo) or use the VPS directly.

### Twilio CLI for Quick Testing

```bash
# Login
twilio login

# List phone numbers
twilio phone-numbers:list

# Update webhook URL to ngrok
twilio phone-numbers:update +639XXXXXXXXX --voice-url https://abc123.ngrok-free.app/voice/incoming

# Watch incoming call logs
twilio calls:list --limit 5
```

## Security Considerations

- Validate Twilio webhook signatures on all incoming requests
- Store API keys in .env file, never in code
- .env and database files excluded from git via .gitignore
- No call audio is stored (only text summaries)
- HTTPS required for Twilio webhook endpoint (Let's Encrypt in prod, ngrok in dev)
