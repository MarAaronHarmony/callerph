# Database Schema

This is the database schema implementation for the spec detailed in @.agent-os/specs/2026-03-11-voice-agent-mvp/spec.md

> Created: 2026-03-11
> Version: 1.0.0

## New Tables

### `clients`

Stores business client configurations.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | Unique client ID |
| name | VARCHAR(255) | NOT NULL | Business name (e.g., "PagePro") |
| phone_number | VARCHAR(20) | NOT NULL, UNIQUE | Twilio phone number assigned to this client |
| prompt_file | VARCHAR(255) | NOT NULL | Path to system prompt markdown file |
| is_active | BOOLEAN | NOT NULL, DEFAULT TRUE | Whether the agent is active for this client |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Record creation time |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Last update time |

**Indexes:**
- UNIQUE INDEX on `phone_number` (lookup by incoming call number)

### `call_logs`

Stores metadata and summary for each call handled.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | Unique call ID |
| client_id | INTEGER | FOREIGN KEY → clients.id, NOT NULL | Which business client this call was for |
| twilio_call_sid | VARCHAR(64) | UNIQUE | Twilio's unique call identifier |
| caller_number | VARCHAR(20) | NOT NULL | Caller's phone number |
| started_at | DATETIME | NOT NULL | Call start timestamp |
| ended_at | DATETIME | NULL | Call end timestamp |
| duration_seconds | INTEGER | NULL | Call duration in seconds |
| conversation_summary | TEXT | NULL | AI-generated summary of the conversation |
| caller_name | VARCHAR(255) | NULL | Name extracted from conversation |
| caller_inquiry | TEXT | NULL | What the caller was asking about |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'in_progress' | Call status: in_progress, completed, failed |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Record creation time |

**Indexes:**
- INDEX on `client_id` (filter calls by client)
- INDEX on `started_at` (sort by date)
- UNIQUE INDEX on `twilio_call_sid` (lookup by Twilio reference)

## SQLModel Definitions

```python
from datetime import datetime
from typing import Optional
from sqlmodel import SQLModel, Field

class Client(SQLModel, table=True):
    __tablename__ = "clients"

    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(max_length=255)
    phone_number: str = Field(max_length=20, unique=True, index=True)
    prompt_file: str = Field(max_length=255)
    is_active: bool = Field(default=True)
    created_at: datetime = Field(default_factory=datetime.utcnow)
    updated_at: datetime = Field(default_factory=datetime.utcnow)

class CallLog(SQLModel, table=True):
    __tablename__ = "call_logs"

    id: Optional[int] = Field(default=None, primary_key=True)
    client_id: int = Field(foreign_key="clients.id", index=True)
    twilio_call_sid: Optional[str] = Field(default=None, max_length=64, unique=True)
    caller_number: str = Field(max_length=20)
    started_at: datetime = Field(default_factory=datetime.utcnow)
    ended_at: Optional[datetime] = Field(default=None)
    duration_seconds: Optional[int] = Field(default=None)
    conversation_summary: Optional[str] = Field(default=None)
    caller_name: Optional[str] = Field(default=None, max_length=255)
    caller_inquiry: Optional[str] = Field(default=None)
    status: str = Field(default="in_progress", max_length=20)
    created_at: datetime = Field(default_factory=datetime.utcnow)
```

## Rationale

- **SQLite for MVP:** Zero setup, single file, perfect for a single-VPS deployment handling < 50 calls/day. Migration to PostgreSQL planned for Phase 5.
- **Separate `clients` table:** Even though MVP has one client (PagePro), the multi-tenant structure is built in from day one — adding a new client is just an INSERT, not a schema change.
- **`conversation_summary` as TEXT:** Generated by Gemini after call ends, stored as plain text. Structured lead extraction (name, inquiry) is done during the call via the system prompt's instructions to Gemini.
- **No audio storage:** Privacy-friendly, reduces storage needs, and not required for the business use case. Summaries capture the essential information.
